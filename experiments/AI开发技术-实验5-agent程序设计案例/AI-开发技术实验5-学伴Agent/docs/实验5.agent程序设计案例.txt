实验5-agent程序设计案例- python程序设计课程学伴 Agent

1、实验目的

通过本实验，学生应认识到，面向程序设计课程的 Agent 系统并不是简单的“模型回答问题”，而是由模型、课程知识、上下文管理、工具权限、代码执行、学习状态、前端交互和测试验证共同构成的工程系统。其中，模型提供语言生成和解释能力；课程知识库提供课程边界；工具门禁控制系统能力暴露范围；Docker 沙箱提供代码运行证据；SQLite 保存学习过程；前端将诊断、指导、练习和评阅组织成可操作的学习体验。只有这些模块协同工作，才能形成可约束、可执行、可追踪的程序设计课程学伴 Agent。具体如下：
1）理解程序设计课程学伴 Agent 与普通聊天机器人的区别。
2）掌握 “Agent = Tutor Model + Learning Harness” 的基本工程结构。
3）能够分析本地 Agent 系统中的前端、服务端、知识库、数据库、工具层和沙箱层之间的协作关系。
4）能够运行并观察一次完整学习闭环，包括诊断、导师指导、练习提交、沙箱运行、评阅反馈和进度更新。
5）能够解释课程知识库、工具门禁、代码沙箱和学习状态在 Agent 系统可靠性中的作用。
6）能够初步识别提示注入、越权工具调用、不安全代码执行、不安全前端渲染和隐藏测试泄露等风险。
7）能够根据运行结果和测试结果撰写实验分析报告。

2、实验内容

1）需求分析
程序设计课程学习中，学生通常需要在概念理解、代码调试、练习提交和反馈改进之间反复切换。普通问答工具虽然可以解释概念和生成代码，但容易出现三个问题：
第一，回答可能脱离当前课程范围，给出“正确但不适合当前学习阶段”的内容；
第二，代码反馈缺少真实运行证据，无法确认学生代码是否真的通过语法、运行或测试；
第三，缺少学习状态记录，系统难以根据学生诊断结果、错题、练习结果和运行记录给出连续化指导。
给定项目围绕这些问题实现了一个本地程序设计课程学伴 Agent。其核心思想是将大语言模型放入一个可约束、可执行、可追踪的 Learning Harness 中。模型负责解释概念、生成提示和组织反馈语言；Harness 负责课程知识约束、上下文构造、工具门禁、学习状态记录、代码沙箱执行、练习评阅和审计追踪。

2）架构设计
前端交互层：负责聊天、诊断、练习、进度和导师反馈展示；
服务端 API 层：负责会话、消息、诊断、练习、进度、数据管理等接口；
课程知识库层：负责提供课程单元、概念、练习和来源材料；
工具与策略层：负责工具注册、工具分组、权限校验、参数校验和审计；
沙箱执行层：负责隔离运行学生 Python 代码或 pytest 任务；
数据持久层：负责保存会话、学习画像、诊断结果、练习提交、学习证据、工具审计和安全事件；
测试验证层：负责验证构建、服务端逻辑、沙箱隔离、前端状态和学习闭环。

3）课程知识库设计
学生需要查看 Python 课程知识库中的 catalog、概念页、练习页和摘要页，理解课程知识库如何限定 Agent 的回答边界。
要求至少选择一个课程概念，例如“字符串”“列表”“函数”“文件处理”或“测试与调试”，分析其在课程知识库中的表示方式，并说明该知识如何进入导师上下文或练习流程。

4）学习闭环设计
学生需要完成一次完整学习流程：
创建或进入一个本地学习会话；
进入诊断入口，完成一道或多道诊断题；
查看系统根据诊断结果给出的学习状态或下一步建议；
通过聊天或练习入口请求相关概念指导；
提交一段 Python 代码；
观察 Docker 沙箱返回的运行结果，包括 stdout、stderr、exit code 或测试结果；
根据导师反馈修改代码；
再次提交代码；
查看练习评阅结果与学习进度是否发生变化。

5）代码沙箱

学生需要通过前端、API 或测试脚本提交不同类型的 Python 代码，观察沙箱执行结果。
建议至少验证以下样例：
正常输出代码；
语法错误代码；
运行时错误代码；
超时代码；
试图访问不允许资源的代码；
pytest 练习评测代码。
学生需要记录每类代码的执行结果，并说明沙箱相比直接在宿主机执行学生代码的优势。



3、实验步骤

1）项目部署与结构分析；
2）Agent Harness 关键模块阅读与流程梳理；
3）学习闭环运行与验证；
4）安全边界与测试结果分析；
5）实验报告整理。

4、实验要求
1）详细记录AI环境的配置和过程；
2）根据实验过程和报告，完成实验PPT和实验报告，内容包括：
系统运行截图；
诊断、练习、代码运行和评阅结果截图；
测试命令输出截图或日志；
如有代码修改，提交修改说明和 diff；
系统结构图和学习闭环流程图。

3）认真总结实验的心得体会，需回答一下问题：
为什么本系统不能简单理解为“调用大模型 API 的聊天窗口”？
Learning Harness 在系统中具体包含哪些模块？
课程知识库如何约束模型回答范围？
工具门禁解决了哪些安全和可靠性问题？
Docker 沙箱为什么是程序设计课程 Agent 的关键模块？
学习证据和学习状态如何支持连续化指导？
本实验能够验证系统的哪些能力？
本实验不能证明哪些能力，例如真实学习效果、性能优势和大规模并发能力？
如果要把该系统用于真实课堂，还需要补充哪些功能？
