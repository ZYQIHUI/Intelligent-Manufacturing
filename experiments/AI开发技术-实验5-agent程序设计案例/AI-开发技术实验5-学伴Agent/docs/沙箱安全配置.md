## 安全配置清单

| 配置项 | 参数 | 作用 | 验证结果 |
|:---|:---|:---|:--:|
| 网络隔离 | `--network none` | 禁止所有网络访问，防止学生代码外连或下载恶意脚本 | ✅ 已通过截图验证（urllib连接被拒） |
| 只读文件系统 | `--read-only` | 根文件系统只读，防止代码修改系统文件 | ✅ 已通过截图验证（写/test.txt被OSError拦截） |
| 权限丢弃 | `--cap-drop ALL` | 移除所有Linux Capabilities，防止特权操作 | ✅ 容器启动正常 |
| 禁止提权 | `--security-opt no-new-privileges` | 防止进程通过setuid等机制提权 | ✅ 容器启动正常 |
| 非root用户 | `--user 65534:65534` | 以nobody用户运行，UID/GID均为65534 | ✅ 容器启动正常 |
| 内存限制 | `--memory 128m` | 限制容器最大内存使用128MB | ✅ 通过命令行参数配置 |
| 进程数限制 | `--pids-limit 64` | 限制容器内最大进程数为64，防止fork炸弹 | ✅ 通过命令行参数配置 |
| 临时目录限制 | `--tmpfs /tmp:rw,noexec,nosuid,nodev,size=32m` | 临时文件系统，不可执行、不可suid、不可设备文件、限制32MB | ✅ 容器启动正常 |
| 自动清理 | `--rm` | 容器执行完毕后自动删除，不留残留 | ✅ 容器执行后即销毁 |
| 工作目录绑定 | `--mount type=bind,source=${workDir},target=/work,readonly=false` | 仅绑定临时工作目录可写 | ✅ 代码文件正常写入 |
| CPU超时 | `timeout ${timeoutSec}s` | 限制代码执行时间，超时发送SIGKILL | ✅ 已通过截图验证（while True被超时终止） |
| Python隔离模式 | `python -I` | 忽略PYTHONPATH和PYTHONSTARTUP等环境变量 | ✅ 容器启动正常 |
| 输出截断 | maxBytes限制 | 限制stdout+stderr最大输出字节数 | ✅ 通过代码配置 |

## Docker Run完整命令

```bash
docker run \
  --rm \
  --network none \
  --read-only \
  --cap-drop ALL \
  --security-opt no-new-privileges \
  --user 65534:65534 \
  --memory 128m \
  --pids-limit 64 \
  --tmpfs /tmp:rw,noexec,nosuid,nodev,size=32m \
  --mount type=bind,source=<workDir>,target=/work,readonly=false \
  --workdir /work \
  python:3.13-slim-bookworm \
  timeout 10.000s \
  python -I /work/main.py
```

---

## 沙箱执行流程

1. 创建临时工作目录（`os.tmpdir()/run_<randomId>`）
2. 将用户代码写入 `main.py`
3. 如有pytest公共测试，写入 `test_public.py`
4. 构建上述docker run命令
5. 执行容器，捕获stdout/stderr和exit code
6. 对输出进行路径脱敏处理（替换实际路径为 `<student-code>`）
7. 删除临时工作目录
8. 返回 `SandboxResult`（含status, stdout, stderr, traceback, duration_ms, truncated）

---

## 状态推断逻辑

| exit code | stderr特征 | status |
|:---|:---|:---|
| 0 | — | `passed` |
| 124 | — | `timeout` |
| 任意 | SyntaxError / IndentationError | `syntax_error` |
| 任意 | MemoryError / Killed | `resource_limit` |
| 任意 | Traceback | `runtime_error` |
| 其他 | — | `failed` |

## 已验证的安全边界

通过6类沙箱测试实际验证以下安全机制生效：

1. **语法错误拦截** — 括号不匹配、非法字符 → `syntax_error`
2. **运行时错误捕获** — ZeroDivisionError → `runtime_error`
3. **超时终止** — 无限循环 → `timeout`
4. **写保护** — 写文件 → `OSError: Read-only file system`
5. **网络隔离** — urllib请求连接外部 → 连接被拒绝

## 相比宿主机直接执行的优点

| 维度 | Docker沙箱 | 宿主机直接执行 |
|:---|:---|:---|
| 文件系统安全 | 只读根文件系统，仅/tmp和/work可写 | 可读写任何用户有权限的文件 |
| 网络隔离 | 完全无网络 | 可访问互联网 |
| 权限控制 | nobody用户，零capability | 当前用户权限 |
| 资源限制 | 内存128MB、进程64个、CPU超时 | 无限制 |
| 残留清理 | --rm自动清除 | 可能留下临时文件 |
| 路径泄露 | 自动脱敏为 `<student-code>` | 暴露真实路径 |
| 可复现性 | 标准镜像，环境一致 | 依赖宿主机环境 |
