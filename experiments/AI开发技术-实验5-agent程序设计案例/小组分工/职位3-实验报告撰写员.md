# 职位 3：实验报告撰写员

## 你的身份
你是 5 人小组中的**实验报告撰写员**，代号 **C**。你是小组的**枢纽**：汇集 A（架构）和 B（测试）的产出，按规范撰写完整实验报告。

## 项目背景
- 实验名称：Python 程序设计课程学伴 Agent
- 项目路径：`coding-mentor-agent/`
- 实验任务文档：`实验5.agent程序设计案例.txt`
- 实验步骤文档：`实验步骤.md`
- 项目仓库：https://github.com/xixu-me/coding-mentor-agent

## 你的工作范围
对应实验步骤文档的**步骤 6.1（报告撰写）**。你**不需要**启动系统、不需要写代码，但需要**细致阅读**所有素材。

## 具体任务清单

### 任务 0：素材收集与阅读
- 完整阅读 `实验5.agent程序设计案例.txt`
- 完整阅读 `实验步骤.md`
- 阅读 A 的所有产出：
  - `小组分工/A-产出/01-项目结构.md`
  - `小组分工/A-产出/02-知识库概念分析.md`
  - `小组分工/A-产出/03-系统结构图.png`
  - `小组分工/A-产出/04-学习闭环流程图.png`
  - `小组分工/A-产出/05-架构分析文档.md`
- 阅读 B 的所有产出（见职位 2 交付物清单）
- 阅读 README.md 和关键源码（不需要全读，但报告中提到的内容要能溯源）

把阅读中遇到的问题记录到：`小组分工/C-产出/00-问题清单.md`

### 任务 1：报告大纲
- 输出：`小组分工/C-产出/01-报告大纲.md`
- 严格按 `实验步骤.md` 第 6.1 节的 7 章结构：
  ```
  1. 实验目的
  2. 实验环境
  3. 实验过程（3.1 部署 / 3.2 架构 / 3.3 学习闭环 / 3.4 沙箱 / 3.5 安全）
  4. 测试结果
  5. 问题与思考（8 个问题）
  6. 实验心得
  7. 附录
  ```

### 任务 2：撰写报告主体
- 输出：`小组分工/C-产出/02-实验报告.md`
- 字数：5000–8000 字
- 格式要求：
  - Markdown 格式
  - 每个章节用 `##` 标题
  - 子章节用 `###`
  - 关键截图用 `![描述](相对路径)` 引用
  - 表格用 Markdown 表格语法

**第 3 章（实验过程）的写作要点**：
- 3.1 部署过程：贴 B 的截图，描述每步命令与预期输出
- 3.2 架构分析：嵌入 A 的系统结构图，说明 7 层协作
- 3.3 学习闭环：嵌入 A 的流程图，描述 B 的实际操作
- 3.4 沙箱测试：贴 B 的 6 张代码截图 + 测试记录表
- 3.5 安全边界：贴 A 的架构分析 + B 的沙箱配置 + B 的风险验证

**第 4 章（测试结果）**：
- 单元测试：通过/失败数，从 B 的 `06-unit-test.log` 摘录关键行
- 学生回路测试：从 B 的 `07-student-loop.log` 摘录关键阶段
- 用代码块引用日志片段

### 任务 3：回答 8 个总结问题（最关键）
- 输出：`小组分工/C-产出/03-八问回答.md`（可独立文件，最终并入报告第 5 章）
- 每个问题 300–500 字，**必须结合 A 和 B 的实证材料**，不能空谈

**问题回答思路**：

1. **为什么本系统不能简单理解为"调用大模型 API 的聊天窗口"？**
   - 列出 7 层架构
   - 强调 KB 约束、工具门禁、沙箱隔离、学习状态
   - 对比"裸 API 调用"的差异

2. **Learning Harness 在系统中具体包含哪些模块？**
   - 服务端 API 路由、KB 加载与检索
   - 工具注册与策略、Sandbox 调用
   - DB 读写、Security 脱敏与限流
   - Agent 提示词构造
   - 给出每个模块的源码路径

3. **课程知识库如何约束模型回答范围？**
   - Tutor 提示词中显式注入课程范围
   - KB 检索工具的返回内容受 catalog 限制
   - 门禁策略控制 KB 工具的 capability
   - 引用 A 的知识库概念分析作为证据

4. **工具门禁解决了哪些安全和可靠性问题？**
   - 防止越权调用
   - 防止敏感信息泄露（脱敏）
   - 防止循环调用死循环
   - 防止 prompt injection 通过工具执行
   - 给出 `src/tools/policy.ts` 的具体策略作为证据

5. **Docker 沙箱为什么是程序设计课程 Agent 的关键模块？**
   - 学生代码不可信
   - 需要真实运行证据（stdout、stderr、exit code）
   - 避免破坏主机
   - 保证测试公平（环境一致）
   - 产出可复现的 learning evidence
   - 引用 B 的沙箱安全配置

6. **学习证据和学习状态如何支持连续化指导？**
   - 诊断结果定位起点
   - evidence 表记录每次运行结果
   - mastery 表汇总掌握度
   - practice_reviews 记录评阅
   - 下一步推荐基于 mastery 阈值
   - 引用 B 的数据库表截图

7. **本实验能够验证系统的哪些能力？**
   - 本地部署、UI 交互
   - 诊断流程、沙箱隔离
   - 安全渲染、知识库检索
   - SQLite 持久化
   - 单元测试与学生回路测试通过
   - 6 类代码沙箱行为符合预期

8. **本实验不能证明哪些能力？**
   - 真实学习效果（需 A/B 实验 + 真实学生）
   - 性能优势（需基准对比）
   - 大规模并发（需压测）
   - 跨班级通用性（需真实课堂）
   - 长期记忆与跨学期学习
   - 多模态输入

### 任务 4：撰写实验心得
- 输出：`小组分工/C-产出/04-实验心得.md`（并入报告第 6 章）
- 字数：500–1000 字
- 涵盖：
  - 收获：理解了"Agent = 模型 + Harness"、理解了本地化安全机制
  - 困难：环境配置 / Docker / API Key
  - 反思：实验设计的局限性
  - 展望：真实课堂所需补充功能（多用户、班级管理、教师后台、学习分析、个性化推荐等）

### 任务 5：附录整理
- 输出：`小组分工/C-产出/05-附录清单.md`
- 包含：
  - 系统结构图（来自 A）
  - 学习闭环流程图（来自 A）
  - 关键截图清单（来自 B）
  - 单元测试与学生回路测试日志摘录
  - 代码 diff（如有，本实验通常无）

### 任务 6：交叉审阅
- 把初稿发给 A 和 B 各看一遍
- A 重点审：架构部分、问题 1–4
- B 重点审：测试部分、问题 5–7
- 收集修改意见，更新到第 3 版

### 任务 7：格式定稿
- 输出最终版：`小组报告/实验报告.md`（注意是"小组报告"目录，不是 C-产出）

  - 引用规范
  - 无错别字
  - 附录完整
