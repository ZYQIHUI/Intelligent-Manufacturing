## 步骤 1：环境准备与依赖检查

> 本节先**检查**已有哪些工具，再按需**安装**缺失的工具。所有安装包都使用 Windows 64 位版本。

### 1.1 检查 Node.js 版本
项目要求 Node.js 24.x：
```powershell
node --version
```
**预期输出**：`v24.x.x`（如 `v24.14.0`）

#### 1.1.1 若未安装 Node.js
1. 打开浏览器，访问 https://nodejs.org/
2. 下载 **LTS 版本**（当前是 24.x 的 LTS）的 **Windows Installer (.msi)** 64-bit
3. 双击运行安装包，按向导操作：
   - 勾选 **"Add to PATH"**（关键！必须勾选）
   - 勾选 **"Install for all users"**（可选）
   - 其余保持默认，点击 Next 直到 Install
4. 安装完成后，**关闭并重新打开 PowerShell 窗口**（让 PATH 生效）
5. 重新执行 `node --version` 验证
6. 截图 `01-node安装成功.png`

**常见问题**：
- 安装后 `node` 仍报"不是内部命令" → 重启 PowerShell；若仍失败，重启电脑
- 想用 nvm 切换版本（可选）：https://github.com/coreybutler/nvm-windows

### 1.2 检查 npm 是否可用
```powershell
npm --version
```
**预期输出**：`10.x` 或更高

#### 1.2.1 若 npm 未随 Node 一同安装
- 正常情况下 npm 会在 Node 安装时自动装上
- 若 `node` 有版本但 `npm` 无：执行 `npm install -g npm` 升级
- 若 npm 安装依赖慢（国内常见），切换镜像：
  ```powershell
  npm config set registry https://registry.npmmirror.com
  ```
  验证：`npm config get registry` 应返回 `https://registry.npmmirror.com/`

### 1.3 检查 Docker 是否可用
```powershell
docker --version
docker info
```
**预期输出**：Docker Desktop 已运行（看到 `Server Version` 字样）。若提示连接失败，启动 Docker Desktop 并等待右下角图标变绿。

#### 1.3.1 若未安装 Docker
**方案 A：安装 Docker Desktop（推荐，图形化）**
1. 访问 https://www.docker.com/products/docker-desktop/
2. 点击 **"Download for Windows"**
3. 双击 `Docker Desktop Installer.exe` 安装
4. 安装过程中：
   - 勾选 **"Use WSL 2 instead of Hyper-V"**（推荐，Win10/11 默认开启 WSL2）
   - 等待安装完成，**重启电脑**
5. 重启后启动 Docker Desktop，等待右下角系统托盘图标**从橙色变为绿色**（表示 Docker 引擎已就绪）
6. 重新打开 PowerShell，验证：
   ```powershell
   docker --version
   docker run hello-world
   ```
   若 `hello-world` 输出 `Hello from Docker!` 则安装成功
7. 截图 `01-docker安装成功.png`

**方案 B：使用 WSL2 + Docker Engine（无 GUI 方案）**
1. 以管理员身份运行 PowerShell：
   ```powershell
   wsl --install
   ```
2. 重启电脑
3. 在 Microsoft Store 安装 Ubuntu 发行版
4. 在 Ubuntu 中安装 Docker Engine（参考 https://docs.docker.com/engine/install/ubuntu/）

**前置条件（Docker Desktop 需要）**：
- Windows 10 64-bit: Home/Pro 21H2 (build 19044) 或更高
- Windows 11 64-bit: 任意版本
- 开启 **WSL 2 功能**：
  ```powershell
  dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
  dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
  ```
  然后重启，再安装 WSL2 Linux 内核更新包：https://wslstorestorage.blob.core.windows.net/wslblob/wsl_update_x64.msi

### 1.4 检查 Python（用于学生回路测试）
```powershell
python --version
```
**预期输出**：`Python 3.x.x`

#### 1.4.1 若未安装 Python
1. 访问 https://www.python.org/downloads/
2. 下载 **Python 3.11.x 或 3.12.x** 的 Windows installer (64-bit)
3. 双击运行：
   - **勾选最下方的"Add python.exe to PATH"**（关键！）
   - 点击 **"Install Now"**
4. 安装完成后，**关闭并重新打开 PowerShell**
5. 验证 `python --version`
6. 验证 pip：
   ```powershell
   python -m pip --version
   ```
7. 截图 `01-python安装成功.png`

**备选方案**：若已安装 Microsoft Store 版 Python，建议卸载后改用 python.org 安装包，避免路径含空格导致脚本问题。

### 1.5 准备 AI API Key
模型调用是导师聊天的前置条件。请准备：
- 任意兼容 OpenAI Responses 接口的服务
- 至少包含：`AI_PROVIDER`、`AI_API`、`AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY`

#### 1.5.1 若已有可用的 API 服务
- OpenAI 官方：https://platform.openai.com/api-keys
- 国内代理（需自行评估合规性）：搜索"OpenAI Responses 兼容 API"
- 本地模型（如 Ollama / vLLM 启动的 OpenAI 兼容服务）：把 `AI_BASE_URL` 指向 `http://127.0.0.1:11434/v1` 之类

#### 1.5.2 若没有 API Key
**方案 A：申请一个免费/低价 Key（最简单）**
- OpenAI 新账号通常有少量免费额度
- 国内有第三方提供低价代理（自行甄别）
- 部分国产模型厂商提供 OpenAI 兼容接口（DeepSeek、月之暗面、智谱等），需查其文档

**方案 B：本地跑一个小模型（最稳）**
1. 安装 [Ollama](https://ollama.com/download)：下载 Windows 版安装
2. 启动 Ollama（系统托盘会有图标）
3. 拉取一个支持中文的小模型：
   ```powershell
   ollama pull qwen2.5:7b
   ```
4. 验证服务可用：
   ```powershell
   curl http://127.0.0.1:11434/v1/models
   ```
   应返回 JSON 列表
5. 在 `.env` 中配置：
   ```ini
   AI_PROVIDER=openai
   AI_API=openai-responses
   AI_BASE_URL=http://127.0.0.1:11434/v1
   AI_MODEL=qwen2.5:7b
   AI_API_KEY=ollama
   ```
   （Ollama 不校验 Key，任意非空字符串即可）

**方案 C：跳过 API Key**
- 如果实在拿不到 Key，导师聊天会返回 `MODEL_UNAVAILABLE`
- 但**沙箱、诊断、知识库、进度跟踪仍然可用**
- 建议实验分两段走：先完成不需要 API Key 的部分，再配置 Key 补做聊天

#### 1.5.3 验证 API Key 是否可用
在配置到 `.env` 之前，可先用 curl 验证：
```powershell
curl -Method POST `
  -Uri "https://api.openai.com/v1/chat/completions" `
  -Headers @{ "Authorization" = "Bearer your-key" } `
  -Body '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"hi"}]}' `
  -ContentType "application/json"
```
若返回 JSON 且无 `error` 字段，则 Key 有效。

## 步骤 2：项目部署

### 2.1 进入项目目录
```powershell
cd coding-mentor-agent
```

```powershell
npm install
```

- 权限问题：以管理员身份运行 PowerShell

### 2.3 复制环境变量模板
```powershell
Copy-Item .env.example .env
```

### 2.4 编辑 `.env` 文件
用记事本或 VSCode 打开 `.env`，按需修改：
```ini
PORT=3000
APP_DATA_DIR=.app
COURSE_KB_ROOT=kb/python-course-kb-practical-python/wiki
COURSE_KB_VERSION=kb-local
ENABLED_BATCH=full
SANDBOX_IMAGE=coding-mentor-python-runner:0.1.0
SANDBOX_TIMEOUT_MS=3000
SANDBOX_PYTEST_TIMEOUT_MS=8000
SANDBOX_MEMORY_MB=128

# 选填：有 Key 才填
AI_PROVIDER=openai
AI_API=openai-responses
AI_BASE_URL=https://api.openai.com/v1
AI_MODEL=gpt-5.5
AI_API_KEY=your-key-here
```

### 2.5 构建 Docker 沙箱镜像
这是**最关键的一步**，因为沙箱执行依赖该镜像：
```powershell
docker build -t coding-mentor-python-runner:0.1.0 -f sandbox-runner.Dockerfile .
```

**预期行为**：
- 拉取 Python 基础镜像
- 安装 pytest 等依赖
- 输出 `Successfully tagged coding-mentor-python-runner:0.1.0`

**验证镜像存在**：
```powershell
docker images | Select-String "coding-mentor-python-runner"
```

### 2.6 启动系统
```powershell

```
**预期输出**：
- 提示 `Server listening on http://127.0.0.1:3000`
- 提示 `Sandbox runner image: coding-mentor-python-runner:0.1.0`
- 可能出现 `MODEL_UNAVAILABLE` 警告（如果没配 Key，可忽略）

### 2.7 浏览器访问

## 步骤 3：项目结构与七层架构分析

### 3.1 浏览顶层目录
```powershell
Get-ChildItem coding-mentor-agent
```

- `README.md` — 项目说明

- `src/` — 源码
- `tests/` — 测试

### 3.2 浏览 src 子目录
```powershell
Get-ChildItem coding-mentor-agent/src
```
**对应 7 层架构**：
| 目录 | 对应层 | 关键文件 |
|---|---|---|
| `src/frontend` | 前端交互层 | React 组件、CodeMirror 编辑器 |
| `src/server` | 服务端 API 层 | HTTP/SSE 路由、会话管理 |
| `src/agent` | Agent 核心 | Tutor 提示词、Pi AI 集成 |
| `src/tools` | 工具与策略层 | 工具注册、权限校验 |
| `src/sandbox` | 沙箱执行层 | Docker 调用 |
| `src/db` | 数据持久层 | SQLite schema |
| `src/security` | 安全相关 | 脱敏、路径校验、限流 |

### 3.3 阅读关键模块
按以下顺序阅读源码（用 VSCode 打开项目）：

**a) 服务入口**：`src/server/main.ts`
- 了解服务器如何启动、路由如何注册
- 找到 `app.get('/api/...')` 与 `app.post('/api/...')` 等接口

**b) 课程知识库**：`src/server/kb.ts`（或类似文件）
- 看知识库如何加载 `kb/python-course-kb-practical-python/wiki/`
- 找出知识库检索的入口函数

**c) 工具注册与门禁**：`src/tools/registry.ts`、`src/tools/policy.ts`
- 列出已注册的工具（KB 查询、进度查询、练习、沙箱等）
- 理解权限校验的流程

**d) 沙箱执行**：`src/sandbox/runner.ts`（或类似）
- 看 Docker 命令如何拼接
- 注意 `network none`、`memory`、`cpus`、`pids-limit` 等参数
- 看 `timeout` 如何实现

**e) 数据库**：`src/db/schema.sql`（或迁移脚本）
- 列出有哪些表（sessions、mastery、evidence、audit、security_events 等）
- 了解每张表存什么

**f) Agent 提示词**：`src/agent/tutor-prompt.ts`（或类似）
- 找出系统提示词
- 看课程知识库内容如何注入

## 步骤 5：安全边界与测试结果分析

### 5.1 阅读沙箱代码的安全设置
