这份实验指导文档要求你围绕一个“Python程序设计课程学伴 Agent”项目，完成从系统部署、代码测试到原理分析的完整过程 。这不仅仅是一个简单的代码编写任务，更侧重于**工程架构分析**和**系统机制验证** 。

### 1. 核心理解目标

你需要通过实验深刻认识到：面向教学的 Agent 系统不仅是调用大模型聊天，而是一个包含**模型、课程知识、上下文管理、工具权限、代码执行（Docker沙箱）、学习状态记录、前端交互和测试验证**的复杂工程系统

（即 Agent = Tutor Model + Learning Harness） 。你需要理解这些模块之间是如何协作的 。

### 2. 实际操作任务

你需要基于提供的 GitHub 项目链接（`coding-mentor-agent`）进行部署，并完成以下实操环节 ：

- **运行学习闭环**：
- 创建并进入本地学习会话 。
- 完成诊断题，查看系统给出的学习状态和建议 。
- 请求概念指导，并提交 Python 代码练习 。
- 观察 Docker 沙箱的返回结果（如 stdout、报错信息、测试结果等） 。
- 根据 Agent 导师的反馈修改并再次提交代码，最后查看评阅结果和进度变化 。

**代码沙箱边界测试**：你需要故意提交不同类型的代码来测试沙箱的反应，并记录结果 。必须测试的类型包括：

- 正常输出的代码 。
- 包含语法错误的代码 。
- 包含运行时错误的代码 。
- 会引起超时的代码 。
- 试图访问不允许资源（越权）的代码 。
- pytest 练习评测代码 。

### 3. 原理分析任务

- **分析课程知识库**：选择一个特定的课程概念（例如“字符串”、“列表”或“函数”等），去系统提供的知识库中查看它是如何表示的，并分析这些知识是如何进入导师的上下文并限制 Agent 回答边界的 。
- **梳理安全与可靠性**：分析工具门禁和代码沙箱是如何防止提示注入、越权调用和不安全代码执行等风险的 。

### 4. 最终需要提交的产物（PPT 与 实验报告）

你需要将上述实操和分析过程整理成报告和 PPT，必须包含以下内容 ：

- **过程记录**：详细记录 AI 环境的配置和部署过程 。
- **截图证据**：包括系统运行截图、诊断/练习/代码运行与评阅的结果截图、测试命令输出或日志的截图 。
- **图表绘制**：绘制系统的结构图以及学习闭环流程图 。
- **代码变更（如有）**：如果在实验中修改了系统源码，需要提交修改说明和 diff 对比 。
- **深度总结与问答**：在报告的心得体会部分，**必须明确回答文档中列出的 9 个关键问题**（涵盖了为什么这不是普通聊天窗口、Learning Harness 的模块构成、知识库的作用、Docker沙箱的重要性、系统能力的验证范围及其局限性等） 。
