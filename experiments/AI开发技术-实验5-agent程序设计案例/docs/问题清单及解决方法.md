## 问题1：练习提交通过后沙箱消失

**现象**：在沙箱中运行Python代码并通过测试后，练习卡片从界面消失，无法继续提交下一次练习。

**原因**：练习合同（practice_contracts）的 status 变为 `completed` 后，前端不再渲染该练习卡片。`loadActivePracticeContractSummary()` 只查询 status IN ('active', 'submitted') 的合同。

**解决方法**：
```sql
-- 在 .app/progress.db 中执行
UPDATE practice_contracts SET status = 'active'
WHERE id = 'prac_2d68b43d32e64a75961f';
```
执行后刷新页面，练习卡片重新出现。

**注意**：运行时错误（如 ZeroDivisionError）不会导致沙箱消失，因为此时 status 仍为 `active`（提交未通过）。只有 pytest 全部通过后 status 变为 `completed` 才会消失。

## 问题2：会话不匹配导致练习不可用

**现象**：浏览器显示错误 "当前练习不存在或已经不是本会话的活动练习"，无法在沙箱中运行代码。

**原因**：系统存在两个会话：
- `sess_cb8c440ad55945ab9449`（旧会话，练习合同的 session_id）
- `sess_2ace76ddfcec4478a793`（新会话，浏览器恢复时自动选择了较新的）

`getOrCreateLocalSession()` 返回最近活跃的会话。浏览器恢复了新会话，但练习合同绑定在旧会话上。`assertActivePracticeSubmission()` 检测到 session_id 不匹配后抛出错误。

**解决方法**：
1. 手动结束新会话，让系统回到旧会话：
```sql
UPDATE agent_sessions SET status = 'ended', ended_at = '2026-06-08T06:28:00'
WHERE id = 'sess_2ace76ddfcec4478a793';
```
2. 确保练习合同状态为 active（参考问题1）
3. 刷新页面

## 问题3：练习提交API返回 output_format 错误

**现象**：通过 `POST /api/exercises/practical-python-1.1/submissions` 提交代码，接口始终返回 `status: "failed"` 且带有 `output_format` 标签，无法获得正常的 pytest 评测结果。

**原因**：练习提交接口期望特定的输出格式或需要特定的提交参数，直接调用 API 不符合其预期格式。

**解决方法**：绕过 API 接口，使用嵌入式 assert 语句在沙箱中直接测试代码：
- 正常输出测试：用 `print()` 直接查看运行结果并手动验证
- 代码正确性测试：在代码末尾内嵌 assert 语句，如 `assert add(2, 3) == 5`，通过沙箱 `run_python` 工具运行，根据是否抛出 AssertionError 判断通过与否

## 问题4：DeepSeek模型生成不符合规范的导师动作

**现象**：导师Agent在指导过程中偶尔生成无效的 `action_kind`（如 `guided_question_missing`），或者生成的JSON结构不符合预期格式，导致前端显示系统错误。

**原因**：DeepSeek模型在生成结构化JSON时偶尔偏离 schema，产生不存在的 action_kind 或缺少必填字段。

**解决方法**：不需要手动干预。系统的动作校验门禁（`validate_tutor_action()`）会自动拦截不符合规范的动作，记录为 `validation_status: "rejected"`，然后触发模型修复机制（`repairs a malformed tutor action once through the external model`）。如果修复后仍不合法，该轮对话会以 VALIDATION_ERROR 结束，不会产生副作用。

**验证**：可在 `tutor_agent_actions` 表中查看被拦截的动作记录：
```sql
SELECT action_kind, validation_status, validation_code
FROM tutor_agent_actions
WHERE validation_status = 'rejected';
```

## 问题5：Python E2E测试无法运行（playwright未安装）

**现象**：运行 `npx vitest run` 时，`student-loop-protocol.test.ts` 中的部分测试调用 Python 子进程失败：
```
ModuleNotFoundError: No module named 'playwright'
```
同时 `tests/e2e/` 目录下的 7 个 Python 脚本全部无法运行。

**原因**：playwright 是浏览器自动化测试框架，不在项目依赖中，需要单独安装。

**解决方法**：
```bash
pip install playwright
python -m playwright install chromium
```
安装后可以通过以下命令运行学生回路测试：
```bash
npm run test:student-loop:local          # 本地单次运行
npm run test:student-loop:strict         # 严格矩阵模式
npm run test:student-loop:realistic      # 真实LLM驱动模式
```

**注意**：playwright 安装的 Chromium 浏览器约 150MB，需要稳定的网络环境。如果仅验证 TypeScript 单元测试，不影响 `npx vitest run` 的核心结果（265/274 通过）。

## 问题6：Docker沙箱文件读取未完全限制

**现象**：沙箱测试中发现 `/etc/passwd` 等世界可读文件仍然可以被学生代码读取并输出内容。

**原因**：Docker 容器的 `--read-only` 参数只禁止写操作，不禁止读取。`/etc/passwd` 的权限为 `-rw-r--r--`（世界可读）。这是 Docker 容器的预期行为，世界可读文件不构成安全风险。

**结论**：此问题无需解决，属于 Docker 沙箱的正常行为。安全敏感的宿主文件（如源代码树、数据库文件、Docker socket）已通过以下方式保护：
- 仅绑定临时工作目录（`--mount type=bind,source=<workDir>,target=/work`）
- 不挂载宿主机目录（`does not mount the host source tree, KB, database, or Docker socket into the runner` 测试通过）
- 只读文件系统阻止写入系统关键路径

## 问题7：根目录截图命名混乱

**现象**：项目根目录下的截图文件使用原始时间戳命名（如 `Snipaste_2026-06-08_14-29-44.png`），无法从文件名判断其内容，查找不便。

**原因**：截图工具 Snipaste 使用截取时间作为默认文件名。

**解决方法**：
1. 逐张查看截图内容
2. 按功能和流程阶段分类：
   - 诊断相关截图 → 保留在根目录或归入 `学习闭环/`
   - 沙箱测试截图 → 归入 `沙箱测试/`
3. 按统一格式重命名：`序号-功能-关键内容.png`，如：
   - `01-诊断首页-字典题目.png`
   - `05-正常输出-passed-HelloPython.png`
   - `12-写文件拦截-ReadOnly文件系统.png`

命名规则：序号 + 功能阶段 + 核心内容描述，使用中划线连接，不使用特殊字符。
