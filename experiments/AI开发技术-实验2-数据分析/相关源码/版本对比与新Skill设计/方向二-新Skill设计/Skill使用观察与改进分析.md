# Skill使用观察与改进分析

> 基于Prompt版和Skill增强版的完整实践，记录对现有Skill的观察和新Skill设计思路

---

## 一、现有Skill使用观察

### 1.1 data-analyst-prompter

**使用场景**：数据预处理阶段

**优势观察**：
- EDA优先的5步检查清单有效避免了"跳步"问题
- Schema注入让AI在写代码前完整理解数据结构
- 假设-验证框架将标签构建从直觉操作升级为可追溯的逻辑链
- 代码执行强制原则杜绝了AI"编造数字"的可能

**不足观察**：
- 覆盖范围仅限数据分析，不涉及后续建模和论文
- 缺少针对中文数据（如`\N`空值标记）的特殊处理提示
- 没有数据质量评估→报告撰写的衔接指导
- 缺失值处理策略比较通用，未针对"极端缺失率分层"做专门设计

### 1.2 math-modeling

**使用场景**：问题一~四全流程

**优势观察**：
- 三阶段协作模式（分析→代码→论文）结构清晰
- 算法资源库（7个文件）覆盖面广，查模型时有据可依
- 角色说明文档（建模手/编程手/论文手）分工明确
- 优秀论文库提供了结构参考

**不足观察**：
- **三阶段是线性的，但我们实际需要迭代**（建模→编码→发现问题→回建模）
- 算法资源偏理论，缺少实战调参指南（如class_weight何时用、GridSearchCV最佳实践）
- 论文阶段默认用docx模板，对LaTeX（cumcmthesis）无专门支持
- 缺少"模型评估标准"的硬性约束（如"必须用CV，不能单次划分"）
- 角色说明是参考文档而非强制流程，AI容易跳过

### 1.3 simplify

**使用场景**：数据预处理代码审查

**优势观察**：
- 三Agent并行审查（复用/质量/效率）覆盖全面
- 质量审查Agent发现了人工易遗漏的`hukou_label`类型转换Bug
- 效率审查提出的向量化优化建议实用

**不足观察**：
- 审查范围限于"变更文件"，对于全新项目可能需要手动指定审查范围
- 缺少数据科学专项审查（如"类别不平衡是否处理了""评估是否用了CV"）
- 审查是"事后"的——如果能"事前"给出规范模板会更好

### 1.4 research-writing

**使用场景**：报告撰写

**优势观察**：
- 30个模板覆盖全流程，场景丰富
- 摘要模板（#23）的4段式结构实用
- 审稿模拟（#16）可提前发现论文问题

**不足观察**：
- **所有模板都是通用学术写作，没有一个针对数学建模LaTeX报告**
- 缺少cumcmthesis模板的专项指导
- 图片/表格标题模板是英文的，中文报告场景不直接适用
- 没有"代码附录如何组织"的指导

## 二、跨Skill的综合观察

### 2.1 核心问题：缺少流水线协调者

现有Skill各自覆盖单一环节，但**没有Skill负责端到端流水线的质量把关**。

```
现有状态：   [data-analyst] → [math-modeling] → [research-writing]
              各自独立           各自独立           各自独立

理想状态：   有一个协调Skill在各阶段之间设置质量门禁：
             数据质量✓ → 统计检验✓ → 模型评估标准✓ → 报告完整性✓
```

### 2.2 核心问题：LaTeX专项支持缺失

我们的报告用LaTeX（cumcmthesis），但所有写作Skill都是通用或docx导向的。

实际遇到的问题（Skill都未覆盖）：
- XeLaTeX编译字体缺失
- 代码附录过长导致PDF溢出
- 封面页需要手动customize
- 图表路径管理

### 2.3 核心问题：数据科学的"硬伤检测"缺失

模型训练中的常见错误，现有Skill不会主动检查：
- 类别不平衡未处理
- 单次划分替代CV
- 默认参数无调优
- 只报告准确率不报告F1/召回率
- 特征重要性来自无importance属性的模型

## 三、新Skill设计思路

基于以上观察，设计2个新Skill：

### 3.1 data-modeling-pipeline（全流程协调Skill）

**定位**：协调数据分析→建模→论文的全流程，设置阶段质量门禁

**核心功能**：
- 阶段间的质量检查点（数据质量✓→统计检验✓→模型评估标准✓→报告完整性✓）
- 数据科学的"硬伤检测"（类别不平衡、CV、调参、指标完整性）
- 中文数据处理专项指导
- 将我们在本次实践中踩过的坑固化为检查规则

**与现有Skill的关系**：不是替代，而是**编排**——在合适时机调用data-analyst-prompter/math-modeling/research-writing，并检查其产出质量

### 3.2 latex-report-generator（LaTeX报告生成Skill）

**定位**：专门针对cumcmthesis模板的数学建模报告生成

**核心功能**：
- cumcmthesis模板使用指南（封面、目录、附录配置）
- 图表路径自动管理
- 代码附录长度控制（firstline/lastline策略）
- 常见LaTeX编译问题速查（字体缺失、中文配置、引用刷新）

**与现有Skill的关系**：补充research-writing在LaTeX场景的空白

---

## 四、新Skill的设计原则

1. **基于实战踩坑**：每个规则来自我们实际遇到的问题
2. **硬性约束优先**：该强制的地方不委婉（如"必须用CV"）
3. **检查清单形式**：让AI逐项核对，不易遗漏
4. **中文场景适配**：不照搬英文模板，针对中文数模报告
5. **最小可行**：先覆盖最高频的问题，后续迭代扩展
